# Experimental Results

This document records the main evaluation outcomes for the FASEROH Symbolic Learning project. The goal of the experiments was to check whether sequence models can reliably learn the mapping from a symbolic input expression to its Taylor expansion around `x = 0` up to fourth order.

The final evaluation was carried out on a 100-example slice of the processed dataset using the repository's evaluation script. Both syntactic correctness and mathematical correctness were measured.

## Dataset Summary

- Number of samples: 5000
- Vocabulary size: 25
- Maximum padded sequence length: 30
- Observed maximum input length: 13
- Observed maximum target length: 26
- Task: fourth-order Taylor expansion generation

The dataset was generated symbolically with SymPy and then tokenized and encoded into fixed-length sequences for training.

## Models Evaluated

### LSTM Seq2Seq

The LSTM model was used as the recurrent baseline. It was trained with scheduled teacher forcing, validation-aware training, checkpoint saving, and standard regularization techniques.

### Transformer Seq2Seq

The Transformer model served as the main architecture for the project. It used positional encoding, attention-based sequence modeling, padding-aware masking, and the same general training and validation framework as the LSTM baseline.

## Evaluation Metrics

Three metrics were used:

- `Token Accuracy`: measures how many predicted tokens match the target tokens
- `Exact Match`: checks whether the full predicted sequence is identical to the target sequence
- `Symbolic Match`: checks whether the predicted and target expressions are mathematically equivalent under SymPy simplification

The symbolic metric is especially important because two expressions can differ in form while still representing the same mathematical object.

## Final Results

### LSTM

- Average token accuracy: `1.0000`
- Exact match: `1.0000`
- Symbolic match: `1.0000`

### Transformer

- Average token accuracy: `1.0000`
- Exact match: `1.0000`
- Symbolic match: `1.0000`

## Example Predictions

### Example 1

- Predicted: `x * ( 6 - x ** 2 ) / 3`
- Target: `x * ( 6 - x ** 2 ) / 3`

### Example 2

- Predicted: `x * ( - 3 * x ** 3 + 4 * x ** 2 - 6 * x + 24 ) / 12`
- Target: `x * ( - 3 * x ** 3 + 4 * x ** 2 - 6 * x + 24 ) / 12`

### Example 3

- Predicted: `x ** 4 / 24 + x ** 3 / 6 + x ** 2 / 2 + x + 1`
- Target: `x ** 4 / 24 + x ** 3 / 6 + x ** 2 / 2 + x + 1`

## Discussion

On the evaluation slice that was tested, both architectures produced perfect scores across token accuracy, exact match, and symbolic equivalence. This indicates that the models learned not only the visible token patterns in the target sequences, but also the underlying symbolic structure well enough to reproduce mathematically correct expansions.

The Transformer remains the stronger model to highlight in presentation and discussion, even though both models performed equally on this evaluated subset. The reason is that the Transformer architecture is more scalable and better suited to longer, more complex symbolic sequence tasks.

The LSTM remains useful as a baseline because it shows that even a recurrent encoder-decoder can learn this task effectively under the current dataset design.

## Reproducibility Note

The reported results above were obtained with:

```bash
python src/evaluation/evaluate_model.py --model lstm --num-examples 100
python src/evaluation/evaluate_model.py --model transformer --num-examples 100
```

Model checkpoint files are intentionally not stored in the repository, but they can be regenerated by running the training scripts included in `src/training/`.
